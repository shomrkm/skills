# shomrkm-slack-notify

shomrkm の個人 Slack ワークスペースの通知チャンネルへの投稿を担う。

## 責務

**このスキルがやること**: 渡された内容を、決まったチャンネルに、決まった書式で投稿する。

**このスキルがやらないこと**: 通知する中身を作ること。何を通知すべきかは呼び出し側が決める。

## 投稿先

| 項目 | 値 |
|---|---|
| チャンネル ID | `C05C6SS2KJA` |
| ツール | Slack MCP の「メッセージ送信」ツール (下記) |

**ツール名は実行環境によって変わる。** 対話セッションでは `mcp__plugin_slack_slack__slack_send_message`、ヘッドレス実行 (`claude -p`) では `mcp__slack__send_message` のように、同じ機能が別名で登録される。

**名前を決め打ちせず、実行時に利用可能なツールから「Slack にメッセージを送信するもの」を選ぶこと。** 見つからない場合は Slack MCP が未接続なので、通知せずその旨を報告して終了する (エラーで落とさない)。

チャンネル ID `C05C6SS2KJA` は環境によらず同じ。

## 投稿ルール

1. **1回の実行 = 1投稿**。複数の対象があってもまとめて1つの投稿にする。対象ごとに投稿すると通知疲れで読まれなくなる
2. **プレーンテキスト + 絵文字**を使う。Block Kit は使わない (個人チャンネルへの単方向通知でインタラクションが不要なため)
3. **要対応のものを先頭に置く**。正常なものは畳んで短く書く。均等に並べると注意を向けるべき対象が埋もれる
4. **詳細は書かない**。Slack は「拾うべきものを見つける索引」として使い、詳細は Notion 側に置いてリンクする
5. **通知する内容が無いときは投稿しない**。空の通知は読まれなくなる原因になる

## 書式

呼び出し側の用途に応じて選ぶ。いずれも1投稿に収める。

### ダイジェスト型 (複数対象の状況報告)

```
📊 <タイトル> — <日付>

⚠️ 要対応 2件
• <対象名> — <状態> · <補足>
  └ 次の一手: <アクション>
• <対象名> — <状態> · <補足>

✅ 順調 2件
• <対象名> (<進捗>)
• <対象名> (<進捗>)

→ 詳細は <リンク先の案内>
```

### 完了報告型 (単一の成果物)

```
📚 <何をしたか> — 「<成果物名>」
   <文脈となる情報>
   → <URL>
```

### エラー型

失敗は必ず通知する。無人実行では失敗が誰にも気づかれないことが最大のリスクになる。

```
⚠️ <何に失敗したか>
   <エラーの概要>
   <部分的に成功したものがあればその件数>
```

## 避けるべき間違い

- ❌ 対象ごとに複数投稿する (1実行1投稿)
- ❌ Notion に書いた内容を Slack にも全文コピーする (Slack は索引)
- ❌ 失敗を黙って終了する (エラーこそ通知する)
- ❌ 通知する中身が無いのに「変更なし」と投稿する (投稿しない)
- ❌ チャンネル ID を推測する (`C05C6SS2KJA` を使う)
