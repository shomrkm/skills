# 運用の詳細

[SKILL.md](../SKILL.md) の手順のうち、必要になったときに読むものをここに置く。

## 静かな時間帯

静かな時間帯は、既定で 18:00 から 09:00 までだ。この時間帯は、監視ループが通知を出さずに溜め、明けたら 1 行にまとめて出す。時間帯は `config.json` の `quiet_hours` で変えられ、`""` にすると無効になる。

この時間帯に Monitor が切れたら、Monitor は張り直さない。人間にも何も書かない。代わりに、`run_in_background` で次のコマンドを 1 回だけ起動する。

```bash
~/secretary/bin/sec follow --once
```

このコマンドは、明けたときのまとめが出ると終わる。その内容を報告してから、Monitor を張り直す。静かな時間帯の前に出ていた行で終わったときは、その行を報告してから、もう一度このコマンドを起動する。


## タスクをどの space に置くか

タスクは herdr の space（ワークスペース）にタブとして開く。秘書は今の space に残り、タスクのタブは秘書の space には開かない。人間がいま話しているタスクだけは、ペインを秘書のタブに並べる。手順は [秘書の横に出すタスク](#秘書の横に出すタスク) にある。

- **関連するタスクは同じ space にする。** `sec new --space <space 名>` を付けると、同じ名前の space があればそこにタブを足し、なければ作る。同じ space のタスクの作業エージェントは、互いに伝言を送れる
- 関連するとは、互いの結果を待つか知る必要がある作業のことだ。例: 同じ機能のバックエンドとフロントエンド（リポジトリごとに分けたタスク）、同じ PR の上に積む作業、ある修正を前提にした後続の修正。リポジトリが同じというだけでは関連とは言わない
- 既存のタスクと関連するなら、`sec list` の `space=` を見て同じ名前を付ける。新しく関連するタスクをまとめるなら、何のまとまりかがわかる短い英語名を付ける（例: `order-api`、`evaluation-csv`）
- どのタスクとも関係なければ `--space` を付けない。そのタスクだけの space ができる（名前はタブと同じ）
- 関連するかどうか迷ったら、起動する前に人間に聞く（例: 「t004 と同じ space に入れる？（order-api）」）。人間が space を指定したら、それに従う

space の最後のタスクを `sec close` すると、space も閉じる。人間が足したタブや `--keep-tab` で残したタブがあれば、space は残る。

## 秘書の横に出すタスク

`sec bring <id>` は、タスクのペインを秘書のペインの右に並べる。向きは `config.json` の `bring_split`（`right` か `down`）で変えられる。フォーカスは移さない。

1. 前に出していたタスクがあれば、そのペインを space に戻す。同じ space の別のタスクがいるワークスペース、なければ space 名のワークスペースに、新しいタブとして足す。どちらもなければ、space を作り直す
2. 指定したタスクのペインを、秘書のタブに動かす。元のタブが空になれば herdr が閉じ、space が空になれば space も閉じる

ペインを動かしても、中の Claude Code は止まらない。別のワークスペースへ動かすと、ペイン ID が変わる。sec は meta.json の `pane`・`tab`・`workspace` を書き直し、前の ID を `pane_aliases` に残す。hook は Claude Code を起動したときの `HERDR_PANE_ID` でタスクを探すので、`pane` と `pane_aliases` の両方と照らし合わせる。

人間が横のペインを自分で別の場所へ動かしていたら、次の `sec bring` はそのペインを動かさず、横に出している印だけを外す。

`sec new` で起動したとき、`sec reply` と `sec choose` で返事を送ったときは、自動で横に出す。止めるには `config.json` の `auto_bring` を `false` にする。秘書が herdr のペインの外で動いていて `HERDR_PANE_ID` がないときは、何もしない。デスクトップアプリでは、`sec bring` はタスクの画面を秘書の画面に重ねて出すだけで、自動では出さない（[SKILL.md](../SKILL.md#秘書の横に出すタスク)）。

## 進み具合のログ（status.tsv）

作業エージェントは `sec note <種類> "<内容>" [--why "<理由>"] [--evidence "<URL やパス>"]` で、タスクフォルダの status.tsv に 1 行足す。どのタスクの行かは、`sec send` と同じく `SECRETARY_TASK_ID` か、起動したときの `HERDR_PANE_ID` で決まる。worker-settings.json で許可してあるので、確認なしで書ける。

| 列 | 中身 |
|---|---|
| `ts` | JST の ISO 8601 の時刻（例: `2026-11-25T10:02:11+09:00`）。マシンのタイムゾーンによらず +09:00 で書く |
| `kind` | `start`・`progress`・`decision`・`blocker`・`human`。`start` は sec が起動と `sec retry` での起動し直しのときに入れ、作業エージェントは書けない |
| `what` | したこと、決めたこと、詰まっていることを 1 行 |
| `why` | 理由。なければ空 |
| `evidence` | PR の URL、コミット、worktree やファイルのパス。なければ空 |

行は追記するだけで、書き換えも削除もしない。`sec note` は、セルの中のタブと改行を空白にし、`=`・`+`・`-`・`@` で始まるセルの頭に `'` を付ける。表計算ソフトで開いても式として動かない。人間がターミナルで読むときは、`column -s$'\t' -t status.tsv` で表になる。

`sec show` は、読んだ行数を meta.json の `status_seen` に記録し、次はそれより後の行だけを出す。`sec cleanup` は、worktree の候補を探すときに status.tsv の中のパスも見る。

## 作業エージェント同士の伝言

同じ space のタスクの作業エージェントは、`sec send <id> "<伝言>"` で相手に直接伝言を送れる。prompt.md には、送り方と、同じ space のタスクの一覧が載る。後から加わったタスクは `sec peers` で見られる。

伝言は、相手の作業エージェントに `[secretary] <送り手> からの伝言` として届く。秘書の監視ループにも、`[secretary] 伝言 <送り手>→<宛先>: <内容>` という記録が出る。デスクトップ通知は出ない。

## 依頼に添える資料

作業エージェントの MCP は会社のアカウントにつながっていて、人間の個人 Notion などは読めない。依頼の元になった資料がそこにあるなら、秘書が本文を取り出して作業エージェントに渡す。

1. 本文を、スクラッチ領域などに Markdown のファイルで書き出す。1 つの資料を 1 つのファイルにし、ファイル名で中身がわかるようにする
2. `sec new ... --attach <ファイル>` で登録する。資料が複数なら `--attach` を繰り返す。sec がファイルを `tasks/<id>/attachments/` にコピーし、prompt.md の「依頼に添える資料」にパスを書く。タスクフォルダは作業エージェントが確認なしで読める

## `.claude/` 配下の許可

`.claude/` は Claude Code の保護パスだ。ただし、タスクの worktree にある `.claude/skills/`・`.claude/commands/`・`.claude/agents/` への Edit / Write は、作業エージェントの hook が確認なしで許可する。`.claude/settings.json` などはこれまでどおり許可待ちになる。
