# 運用の詳細

[SKILL.md](../SKILL.md) から参照される、必要になったときに読む手順。

## 静かな時間帯

静かな時間帯は、既定で 18:00 から 09:00 までだ。この時間帯は、監視ループが通知を出さずに溜め、明けたら 1 行にまとめて出す。時間帯は `config.json` の `quiet_hours` で変えられ、`""` にすると無効になる。

この時間帯に Monitor が切れたら、Monitor は張り直さない。人間にも何も書かない。代わりに、`run_in_background` で次のコマンドを 1 回だけ起動する。

```bash
~/secretary/bin/sec follow --once
```

このコマンドは、明けたときのまとめが出ると終わる。その内容を報告してから、Monitor を張り直す。静かな時間帯の前に出ていた行で終わったときは、その行を報告してから、もう一度このコマンドを起動する。


## タスクをどの space に置くか

タスクは herdr の space（ワークスペース）にタブとして開く。秘書は今の space に残り、タスクのタブは秘書の space には開かない。人間がいま話しているタスクだけは、ペインを秘書のタブに並べる（[秘書の横に出す](#秘書の横に出す)）。

- **関連するタスクは同じ space にする。** `sec new --space <space 名>` を付けると、同じ名前の space があればそこにタブを足し、なければ作る。同じ space のタスクの作業エージェントは、互いに伝言を送れる
- 関連するとは、互いの結果を待つ・知る必要がある作業のこと。例: 同じ機能のバックエンドとフロントエンド（リポジトリごとに分けたタスク）、同じ PR の上に積む作業、ある修正を前提にした後続の修正。リポジトリが同じというだけでは関連とは言わない
- 既存のタスクと関連するなら、`sec list` の `space=` を見て同じ名前を付ける。新しく関連するタスクをまとめるなら、何のまとまりかがわかる短い英語名を付ける（例: `order-api`、`evaluation-csv`）
- どのタスクとも関係なければ `--space` を付けない。そのタスクだけの space ができる（名前はタブと同じ）
- 関連するかどうか迷ったら、起動する前に人間に聞く（例: 「t004 と同じ space に入れる？（order-api）」）。人間が space を指定したら、それに従う

space の最後のタスクを `sec close` すると、space も閉じる。人間が足したタブや `--keep-tab` で残したタブがあれば、space は残る。

## 秘書の横に出す

`sec bring <id>` は、タスクのペインを秘書のペインの右に並べる。向きは `config.json` の `bring_split`（`right` か `down`）で変えられる。フォーカスは移さない。

1. 前に出していたタスクがあれば、そのペインを space に戻す。同じ space の別のタスクがいるワークスペース、なければ space 名のワークスペースに、新しいタブとして足す。どちらもなければ、space を作り直す
2. 指定したタスクのペインを、秘書のタブに動かす。元のタブが空になれば herdr が閉じ、space が空になれば space も閉じる

ペインを動かしても、中の Claude Code は止まらない。別のワークスペースへ動かすとペイン ID が変わるので、sec は meta.json の `pane`・`tab`・`workspace` を書き直し、前の ID を `pane_aliases` に残す。hook は、起動したときの `HERDR_PANE_ID` を `pane_aliases` からも引く。

人間が横のペインを自分で別の場所へ動かしていたら、次の `sec bring` はそのペインを動かさず、表示中の印だけを外す。

`sec new` で起動したとき、`sec reply` と `sec choose` で返事を送ったときは、自動で横に出す。止めるには `config.json` の `auto_bring` を `false` にする。秘書が herdr のペインの外で動いているとき（`HERDR_PANE_ID` がないとき）は、何もしない。

## 作業エージェント同士の伝言

同じ space のタスクの作業エージェントは、`sec send <id> "<伝言>"` で相手に直接伝言を送れる。prompt.md には、送り方と、同じ space のタスクの一覧が載る。後から加わったタスクは `sec peers` で見られる。

伝言は、相手の作業エージェントに `[secretary] <送り手> からの伝言` として届く。秘書の監視ループにも、`[secretary] 伝言 <送り手>→<宛先>: <内容>` という記録が出る。デスクトップ通知は出ない。

## 依頼に添える資料

作業エージェントの MCP は会社のワークスペースにつながっていて、人間の個人 Notion などは読めない。依頼の元になった資料がそこにあるなら、秘書が本文を取り出して作業エージェントに渡す。

1. 本文を、スクラッチ領域などに Markdown のファイルで書き出す。1 つの資料を 1 つのファイルにし、ファイル名で中身がわかるようにする
2. `sec new ... --attach <ファイル>` で登録する。資料が複数なら `--attach` を繰り返す。ファイルは `tasks/<id>/attachments/` にコピーされ、prompt.md の「依頼に添える資料」にパスが載る。タスクフォルダは作業エージェントが確認なしで読める

## `.claude/` 配下の許可

`.claude/` は Claude Code の保護パスだが、タスクの worktree の中の `.claude/skills/`・`.claude/commands/`・`.claude/agents/` への Edit / Write は、作業エージェントの hook が確認なしで許可する。`.claude/settings.json` などはこれまでどおり許可待ちになる。
